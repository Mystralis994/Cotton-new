# Cotton Candy Sticker — Security Specification (Phase 5 Final Hardening)

## 1. Data & Platform Invariants
1. **Identity & Privilege Isolation**: Users may only read or update their own `/users/{userId}` document (`displayName`, `photoURL`) and may never assign themselves `role: "admin"`. Admin operations require `email_verified == true` and either the bootstrapped admin email (`jellyzizy@gmail.com`) or an `/admins/{uid}` record.
2. **Published-Only Public Catalog & Watermarked Previews**: Unauthenticated visitors and non-admin customers may only read `/products/{productId}` documents where `published == true`. Public catalog assets are served exclusively from `/previews/*.jpg` (EXIF-stripped, max `720px`, diagonal `COTTON CANDY STICKER` watermark); uncompressed originals reside only in `/private-vault/originals/` (excluded from Vite build and HTTP `403` blocked by `server.ts`).
3. **Strict Manual WhatsApp Delivery Model**: Zero customer-facing self-download portals, signed storage download links, or `assetKey` disclosures exist anywhere in customer UI (`/orders`, `/order-payment`, `/product`, footer, or email templates). Paid digital files are delivered manually by the store owner via official WhatsApp (`+6281238078363`).
4. **Enabled-Only Payment Methods & Admin-Only Config**: Customers may only read `/paymentMethods/{methodId}` where `enabled == true`. Disabled methods, payment mutations, `/paymentAdminConfig/{configId}`, and `/adminAuditLogs/{logId}` are strictly restricted to verified admins (`isAdmin()`).
5. **Trustless Checkout Integrity & Express Server Validation**:
   - Client checkout routes WhatsApp orders through `POST /api/orders/validate-whatsapp` (`server.ts`), which enforces sliding-window rate limits (`10/60s` per IP, `6/60s` per UID -> `429`), 15-second duplicate-order fingerprinting (`409`), authoritative catalog pricing lookups, and tamper detection (`400`).
   - Firestore `/orders/{orderId}` creation by customers requires `isVerifiedUser()`, `total == subtotal`, `paymentStatus == "unpaid"`, empty verification fields, `downloadAuthorized == false`, atomic `{orderId}-item-1` existence (`existsAfter`), and valid `pending_contact` / enabled `paymentMethodId`.
6. **Immutable Audit Trail & Safe Backup Restore**: Administrative backup restores validate JSON structure (`schemaVersion: "1.0"`, `storeName: "Cotton Candy Sticker"`, `<= 5MB`), reject unsafe URLs (`javascript:`, `//`, `data:image/svg+xml`), automatically trigger a pre-restore safety JSON download, preserve immutable `createdAt` timestamps on existing documents, and write append-only records to `/adminAuditLogs/{logId}` (`update, delete: false`).
7. **Storage & Transport Protections**: `/storage.rules` enforces admin-only writes (`<= 2MB`, raster `PNG`/`JPG`/`WebP` only) and denies public/customer listing or writes. `server.ts` enforces baseline security headers (`X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy`) without blocking AI Studio iframe embedding, and returns `403` for private paths (`/private-vault`, `/firestore.rules`, `/storage.rules`, `/.env`, `..`, etc.).
8. **Firebase App Check Integration**: `src/lib/firebase.ts` initializes `ReCaptchaV3Provider` when `VITE_FIREBASE_APP_CHECK_SITE_KEY` / `recaptchaSiteKey` is configured, exposing transparent fallback telemetry to the Admin Dashboard.

## 2. Adversarial Attack Payloads ("Dirty Dozen+")
1. **Self-Role Escalation (`users`)**: User creates `/users/u1` with `{ role: "admin", ... }` -> `PERMISSION_DENIED`.
2. **Shadow Field Injection (`users` / `orders`)**: User updates `/orders/ord1` adding `{ isVerified: true }` -> `PERMISSION_DENIED`.
3. **Cross-User Order & PII Read (`orders`)**: User `u2` reads `/orders/ord_u1` -> `PERMISSION_DENIED`.
4. **Disabled Payment Method Exposure (`paymentMethods`)**: Customer gets or queries `/paymentMethods/pm_disabled` where `enabled == false` -> `PERMISSION_DENIED`.
5. **Private Admin Payment Config & Audit Log Read (`paymentAdminConfig` / `adminAuditLogs`)**: Customer reads `/paymentAdminConfig/default` or `/adminAuditLogs/log1` -> `PERMISSION_DENIED`.
6. **Checkout With Disabled Payment Method (`orders`)**: Customer creates `/orders/ord1` with `paymentMethodId: "pm_disabled"` -> `PERMISSION_DENIED`.
7. **Price & Total Tampering (`server.ts` & `orders`)**: Client submits `clientTotal: 0.01` to `/api/orders/validate-whatsapp` (`HTTP 400`) or writes mismatched `total` directly to Firestore (`PERMISSION_DENIED`).
8. **Client-Side Self-Approval (`orders`)**: Customer creates or updates `/orders/ord1` setting `paymentStatus: "paid"` or `downloadAuthorized: true` -> `PERMISSION_DENIED`.
9. **Abusive Checkout Flood / Duplicate Replay (`/api/orders/validate-whatsapp`)**: Rapid identical order replay triggers `HTTP 409`; exceeding 10 requests/60s per IP or 6 requests/60s per UID triggers `HTTP 429` + `Retry-After`.
10. **Path Traversal & Original Artwork Scraping (`server.ts`)**: Requesting `/private-vault/originals/...`, `/src/assets/images/pack_...`, `/firestore.rules`, `/.env`, or `../package.json` -> `HTTP 403`.
11. **Audit Log Tampering (`adminAuditLogs`)**: Any user or admin attempts to update or delete an existing `/adminAuditLogs/{logId}` entry -> `PERMISSION_DENIED`.
12. **Unverified Email Admin Spoof or Unverified Owner Read (`paymentMethods` / `orders`)**: Token claims `email: "jellyzizy@gmail.com"` with `email_verified: false`, or forged JWT posted to `/api/auth/verify-token` -> `PERMISSION_DENIED` / `HTTP 401`.
13. **Unsafe Image / Link URI & Malicious Backup Restore Injection**: Submitting `javascript:alert(1)` or `data:image/svg+xml;base64,...` in product/payment URLs, order proof links, or backup JSON restore payloads -> blocked by `validateBackupPayload()`, `isSafeImageUrl()`, `SafeImage`, and `firestore.rules`.
